# W9.UI / W2.UI — Runbook kiểm UI bằng CLI/API (chỉ kiểm, không đổi UI)

Phạm vi: các mục W2.UI và W9.UI trong `docs/plan/Work-Graph-fix.md` (mục 13.5 dòng W2 UI, bảng 34.4 dòng "W2.UI / W9.UI"). Runbook này **chỉ mô tả cách kiểm** trên harness local. Không sửa renderer, reducer hay CSS. Mục nào cần đổi UI thì ghi thành đề xuất riêng ở cuối file kiểm (mục 7) để chủ dự án duyệt. CUA chỉ dùng cho **một** lần xác nhận cuối, kèm screenshot. Không dùng CUA để tìm lỗi.

Tên W9.UI để phân biệt với W9 recorder/CDP (`docs/plan/W9-recorder-cdp-evidence.json`).

## 0. Chuẩn bị

- Harness chạy **code của nhánh cần kiểm** (B hoặc `vorflux/*`). Ghi `git rev-parse HEAD` và `git status --porcelain` vào file kiểm. Không dùng UI đang chạy source khác để kết luận.
- Model: OpenCode `space-bunny-free`. Session/DB/workspace riêng cho lượt kiểm.
- Biến dùng chung:

```bash
H=http://127.0.0.1:${BOXFOX_HARNESS_PORT:-3102}/api/agent
OUT=.tmp/w9ui/$(date -u +%Y%m%dT%H%M%SZ); mkdir -p "$OUT"
curl -s "$H/health" | tee "$OUT/health.json"      # status ok + version
curl -s "$H/runtime-info" | tee "$OUT/runtime.json"   # limits/capabilities
```

- Cần một session có ít nhất: một run Work Graph đã xong có review, một run `partial` hoặc `error`, hai child (A, B) có nhiều event, và một artifact > 20k ký tự. Lấy ID:

```bash
SID=<session id>
curl -s "$H/sessions/$SID" > "$OUT/session.json"
curl -s "$H/sessions/$SID/work" > "$OUT/work.json"
jq -r '.runs[] | [.runId, .status, .review.status] | @tsv' "$OUT/work.json"
```

Mỗi mục dưới đây ghi: lệnh, kết quả mong đợi (oracle), cách lưu bằng chứng. Kết quả đỏ giữ nguyên trong file kiểm, không chạy lại để "làm xanh".

## 1. Đổi child nhanh không lẫn nội dung (W2.UI: reset content/loading theo child ID)

```bash
CA=<childA>; CB=<childB>
curl -s "$H/sessions/$CA" > "$OUT/childA.json"
curl -s "$H/sessions/$CB" > "$OUT/childB.json"
# Gọi xen kẽ nhanh, mô phỏng người dùng bấm qua lại:
for i in 1 2 3 4 5; do
  curl -s "$H/sessions/$CA" -o "$OUT/a$i.json" & curl -s "$H/sessions/$CB" -o "$OUT/b$i.json" & wait
done
python3 - "$OUT" "$CA" "$CB" <<'EOF'
import json, sys
out, ca, cb = sys.argv[1:]
for i in range(1, 6):
    a = json.load(open(f"{out}/a{i}.json")); b = json.load(open(f"{out}/b{i}.json"))
    seq_a = {e["seq"] for e in a.get("events", [])}; seq_b = {e["seq"] for e in b.get("events", [])}
    # `seq` là khoá AUTOINCREMENT toàn bảng events (memory/session_store.py), nên hai child
    # không bao giờ được chia sẻ một seq.
    print(i, "idA ok:", a.get("id") == ca, "idB ok:", b.get("id") == cb, "seq chung:", sorted(seq_a & seq_b)[:5])
EOF
```

Oracle:
- Mỗi phản hồi `GET /sessions/{child}` có `id` đúng child đã hỏi, và tập `seq` của A, B rời nhau (không event nào của A nằm trong B và ngược lại).
- `events` dùng `after=<seq>` tăng dần khi poll tiếp: `curl -s "$H/sessions/$CA?after=<lastSeq>"` không trả lại event cũ.

Đây là kiểm phía API. Lỗi reset trong renderer (giữ content của A khi đã chọn B) chỉ thấy qua UI, nên **một** lần CUA cuối: chọn A, rồi B ngay khi A đang loading, chụp màn hình. Expected: panel hiển thị tiêu đề/ID của B, không có đoạn text của A. Lưu `"$OUT/cua-switch.png"`.

## 2. Trạng thái và badge "reviewed" (W2.UI badge completed/reviewed)

```bash
jq '[.runs[] | {runId, status, review: .review.status,
     reviewedSet: (.reviewedSet // null),
     nodes: [.nodes[] | {id, stages: (.stages | map_values({status, verdict: (.rounds[-1].verdict // null)}))}]}]' \
   "$OUT/work.json" > "$OUT/status-matrix.json"
python3 - "$OUT/status-matrix.json" <<'EOF'
import json, sys
bad = []
for run in json.load(open(sys.argv[1])):
    if run["status"] in ("partial", "error", "failed", "cancelled"):
        for node in run["nodes"]:
            for name, st in node["stages"].items():
                if st.get("verdict") == "ok" and st.get("status") not in ("done", "completed"):
                    bad.append((run["runId"], node["id"], name, st))
    rs = run.get("reviewedSet")
    if rs and rs.get("stale"):
        print("stale reviewedSet (không được hiện badge reviewed):", run["runId"])
print("violations:", bad)
EOF
```

Oracle:
- Run `partial`/`error` không có stage nào mang `verdict: ok` mà chưa hoàn tất, và không có `reviewedSet` hợp lệ.
- Badge "reviewed" chỉ hợp lệ khi `reviewedSet` có mặt **và** `stale == false` (trường do W6.2.BIND thêm; nếu nhánh đang kiểm chưa có `reviewedSet` thì ghi "không áp dụng", không suy diễn).
- "completed" (child kết thúc) khác "reviewed" (đã qua review). Ghi bảng `runId | status | review.status | reviewedSet.stale | badge mong đợi`.

## 3. Link artifact đúng version (W9.UI artifact/version/file links)

```bash
RID=<runId>; AID=<artifactId>
curl -s "$H/sessions/$SID/work/runs/$RID/artifacts/$AID?offset=0&limit=8000" > "$OUT/artifact-0.json"
jq '{artifactId, version, contentHash, chars, nextOffset}' "$OUT/artifact-0.json"
# Đọc hết các trang rồi so hash:
python3 - "$H" "$SID" "$RID" "$AID" "$OUT" <<'EOF'
import hashlib, json, sys, urllib.request
h, sid, rid, aid, out = sys.argv[1:]
offset, parts, meta = 0, [], None
while offset is not None:
    url = f"{h}/sessions/{sid}/work/runs/{rid}/artifacts/{aid}?offset={offset}&limit=8000"
    page = json.load(urllib.request.urlopen(url))
    meta = meta or page
    parts.append(page["content"]); offset = page.get("nextOffset")
text = "".join(parts)
digest = hashlib.sha256(text.encode("utf-8")).hexdigest()
print(json.dumps({"chars": len(text), "contentHash": meta.get("contentHash"), "sha256": digest,
                  "match": digest == meta.get("contentHash"), "version": meta.get("version")}))
open(f"{out}/artifact-full.txt", "w", encoding="utf-8").write(text)
EOF
```

Oracle:
- `sha256(UTF-8 toàn văn) == contentHash`, `len == chars`, phần cuối của artifact > 20k có mặt.
- `version` trùng version mà `GET /work` ghi ở `nodes[].stages[].artifact` cho đúng stage/round. Link trong UI phải trỏ đúng `runId/artifactId/version` này.
- Đã biết từ mục 15 Work-Graph-fix: `PlanPanel.tsx` dùng MarkdownRenderer không có `onOpenFile`, nên link basename có thể mở sai chỗ. Ghi kết quả CUA (một lần) nếu thấy, **không sửa**.

## 4. Copy/export UTF-8

Lấy chuỗi mà nút copy/export tạo ra. Trên API: phần `content` artifact (mục 3) là nguồn. Nếu UI có export file thì lưu file đó vào `"$OUT/export.md"` (một lần CUA, hoặc gọi đúng hàm export qua test frontend hiện có).

```bash
python3 - "$OUT/artifact-full.txt" "$OUT/export.md" <<'EOF'
import hashlib, re, sys, unicodedata
src = open(sys.argv[1], encoding="utf-8").read()
try:
    exp = open(sys.argv[2], encoding="utf-8").read()
except FileNotFoundError:
    exp = None
print("src NFC:", unicodedata.is_normalized("NFC", src))
if exp is not None:
    print("byte-equal:", hashlib.sha256(src.encode()).hexdigest() == hashlib.sha256(exp.encode()).hexdigest())
    print("export NFC:", unicodedata.is_normalized("NFC", exp))
    print("diagnostic leaks:", re.findall(r"WORK_[A-Z_]+|errorCode|\[Diagnostic:[^\]]*\]|tools_run=", exp)[:10])
    urls_src = set(re.findall(r"https?://[^\s)>\]]+", src)); urls_exp = set(re.findall(r"https?://[^\s)>\]]+", exp))
    print("URL thiếu/bị cắt:", sorted(urls_src - urls_exp)[:10])
EOF
```

Oracle: byte-equal với artifact (hoặc khác đúng ở phần header export đã định nghĩa), NFC, URL đầy đủ, có dấu tiếng Việt đúng, không chuỗi diagnostic (`WORK_`, `errorCode`, `[Diagnostic: ...]`, `tools_run=`).

## 5. Compatibility client cũ

Client cũ không biết `hasMore`/`nextAfter` (W7.1), `findings` có cấu trúc (W6.1.3), `reviewedSet` (W6.2.BIND). Kiểm bằng snapshot JSON so với schema cũ:

```bash
git show 68ecdf0:backend/src/agentbox/agent_core/work_graph.py > "$OUT/work_graph_old.py"   # mốc schema cũ
python3 - "$OUT/work.json" <<'EOF'
import json, sys
OLD_RUN_KEYS = {"runId", "sessionId", "title", "goal", "flow", "status", "revision", "autopilot",
                "createdAt", "updatedAt", "nodes", "waves", "issues", "review", "verificationVersion",
                "checks", "requests", "grants", "handoffs", "handoffActions", "mainDecisions"}
data = json.load(open(sys.argv[1]))
for run in data["runs"]:
    missing = OLD_RUN_KEYS - set(run)
    print(run["runId"], "thiếu khoá cũ:", sorted(missing), "khoá mới:", sorted(set(run) - OLD_RUN_KEYS))
    for node in run["nodes"]:
        for name, st in node["stages"].items():
            for rnd in st.get("rounds") or []:
                assert isinstance(rnd.get("findings"), (str, type(None))), ("findings đổi kiểu", run["runId"], node["id"])
EOF
```

Oracle: không thiếu khoá cũ, khoá cũ giữ kiểu (ví dụ `rounds[].findings` vẫn là chuỗi bounded; dữ liệu có cấu trúc phải nằm ở khoá mới). Khoá mới chỉ được cộng thêm. Với events: `GET /sessions/{sid}` vẫn trả `events` là list; `hasMore`/`nextAfter` là khoá cộng thêm.

## 6. Capability, pilot, rollback

```bash
curl -s "$H/health"; curl -s "$H/runtime-info" | jq '.features // .capabilities // .limits'
```

Oracle: client chỉ bật hiển thị mới khi backend báo capability tương ứng. Rollback (chạy lại client cũ trên DB mới) không đổi run failed/partial thành pass: lặp lại mục 2 trên cùng DB sau rollback, ma trận trạng thái phải giống hệt (so `sha256` của `status-matrix.json`).
