# BoxFox Router v1 integration contract

Runtime: Node 24 ESM; HTTP on 127.0.0.1:3101 in development. All frontend traffic is same-origin via Vite proxy. Production serves the built frontend on 3100. Provider types are in `frontend/src/types/provider.ts`.

Admin requests use `Content-Type: application/json` for writes and `X-BoxFox-Admin: 1`. Server checks exact allowed Origin + Host for browser calls and rejects cross-origin/admin calls without this header. Only loopback deployment is supported. External `/v1` endpoints require a generated client Bearer key; internal generation uses admin checks. `/api/router/health` is public read-only.

Responses: JSON objects; errors `{error:{code,message,retryable}}` with safe messages. GET `/api/router/state` returns ProviderSnapshot. GET `/api/router/providers`, GET `/api/router/providers/:id`, and PUT `/api/router/providers/:id` body `{roundRobin?,connectionOrder?}` expose catalog/detail and account selection policy. GET `/api/router/connections`, POST `/api/router/connections` body `{providerId,name,apiKey?,endpoint?,projectId?}`, PATCH `/api/router/connections/:id` body `{name?,apiKey?,endpoint?,projectId?,enabled?,autoSync?,enabledModelIds?,customModel?,modelPricing?}`, DELETE same URL disconnects/deletes binding (409 `KEYS_PRESENT` while the key ring still holds keys). POST `/:id/test` discovers models; POST `/:id/models/refresh`; POST `/:id/models/:modelId/test` performs real inference; GET `/:id/quota` refreshes quota.

Key ring (round 29): one connection may hold up to 10 credentials, and every key is a row of the existing `credentials` table — `connection.keys = [{id,label,prefix,createdAt,lastUsedAt},…]` in try order, where `keys[].id` IS that row's id. No crypto changes: the blob's AAD is the row id, so moving a key between connections is a data operation on `records` and no ciphertext is ever re-encrypted. The top key that is not cooling serves first; there is no rotating cursor. A provider 429 parks exactly the key it came from and the turn continues on the next key of the ring while nothing has been streamed to the client; a request-scoped 4xx, a 5xx and an AUTH refusal keep their existing rules and never rotate a key. The window is 30 s when the provider sends no `Retry-After`, may only be raised by that header, and never exceeds 120 s — the 120 s cap is a project convention with two reasons: an absurd header must not hide a key from rotation for long, and the window stays near the harness retry cadence (`RATE_LIMIT_MIN/MAX = 2/30 s`, `RETRY_BUDGET_SECONDS = 60`). Cooldown belongs to the KEY, not to a key+model pair. When every key is parked the engine throws the provider's own last error unchanged (`code`, `message`, `status`, `retryAfterMs`) and that turn costs zero provider calls, because the park check happens before the adapter is called. `state` is one of `ready|cooling|exhausted|error` (`exhausted` = cooling after a quota-shaped 429, matched by `/quota|usage limit|exhaust|hạn mức/i`); `resetAt` comes from the connection quota when the provider publishes one. Only `lastUsedAt` is persisted, inside the connection write the success path already performs; `state`/`cooldownUntil`/`lastError*` live in memory, so a restart puts every key straight back into rotation. An Antigravity token refresh belongs to ONE key: it re-writes only the row of the key that served the turn — never the top key of the ring — and keeps that key's own refresh token, so one connection can hold two Google accounts without one account's grant being overwritten by the other's. Routes, in the shape the interface was built against:
- `POST /api/router/connections/:id/keys` body `{label?,key?}` => 201 decorated connection; appends to the END of the ring, `key` required unless the provider is anonymous, default label `Key <n>`.
- `PATCH /api/router/connections/:id/keys/:keyId` body `{key?,label?}` => 200; rewrites that one key or its label and deliberately does NOT reset `models` (the endpoint did not change) — the legacy `PATCH /api/router/connections/:id` body `{apiKey}` keeps its old behaviour, model reset included. A key whose secret is rewritten — through either route — starts from a clean slate: its cooldown and its last error are cleared, exactly as if that key had answered a probe.
- `DELETE /api/router/connections/:id/keys/:keyId` => 200; dropping the last key empties the ring but leaves the connection in place with `credentialPresent:false`, `authState:'required'` and out of routing.
- `POST /api/router/connections/:id/keys/:keyId/try` body `{modelId?}` => 200 `{connection,probe}`; clears that key's cooldown and last error and pins `activeKeyId`; with a `modelId` it runs one real probe pinned to that key (a probe 429 parks it again), without one `probe` is `null`.
- `POST /api/router/connections/:id/keys/import` body `{fromConnectionId}` => 200; moves every key of the source to the END of the target ring, leaves each row's ciphertext untouched, empties the source ring and keeps the source connection alive; refuses a missing or self source (400), a missing source or target (404), a different provider or endpoint (400), a disabled target, a drained source and a target already holding 10 keys (400).

Deleting a connection whose ring still holds keys is a 409 `KEYS_PRESENT` — it would drop credentials the ring still owns, so empty the ring first. GET `/api/router/connections` serves the same decorated records as GET `/api/router/state` (`keys` and `activeKeyId` included); a connection with no credential row — or one whose row no longer decrypts, e.g. a database restored without its master key — has no `keys` field at all, so the interface falls back to the legacy single-key row and the connection stays deletable instead of taking the whole page down with it. Nothing but `id`, `label`, `prefix` (at most the first 6 characters of a secret), `state`, `cooldownUntil`, `resetAt`, `lastErrorCode`, `lastErrorMessage` and `lastUsedAt` ever leaves the router — never a raw key, blob, ciphertext or hash.
Search providers (Settings → Provider → Web Search): the tab stores the API keys of search providers with the same machinery the key ring already uses — every key is a row of the `credentials` table (AES-256-GCM, AAD = the row id `search:<providerId>`) — so no crypto or schema change was needed, and model routing is untouched. `SEARCH_PROVIDER_CATALOG` in `src/search.mjs` is the single source of truth for the 8 entries in interface order — `brave`, `tavily`, `exa`, `parallel`, `firecrawl`, `searxng`, `cloudflare`, `custom` — and for each one's `requires` (fields the entry cannot be saved without: `apiKey` for the keyed providers, `endpoint` for searxng, `accountId` + `apiKey` for cloudflare, `endpoint` for custom) and `optional` (`apiKey` for custom). A view is `{id,name,requires,optional,envKeys,icon,credentialPresent,hasSecret,prefix,endpoint,accountId,lastTestedAt,lastTest}`; `prefix` is at most the first 6 characters of the key plus `…`, exactly like `headOf()` in the key ring, and the raw key leaves the router through two routes only — `POST /api/router/search/providers/:id/reveal` (the interface's own Show button) and `GET /api/router/search/resolve` (the harness's read contract over loopback). Routes, all behind the admin gate and none in `BRIDGE_PATHS`: `GET /api/router/search` ⇒ `{activeProviderId,revision,providers:[view]}` (`activeProviderId:null` is the built-in keyless path of round v1); `POST /api/router/search/providers` body `{providerId,apiKey?,endpoint?,accountId?}` ⇒ 201 view, 409 `ALREADY_CONFIGURED`, 400 `CREDENTIAL_REQUIRED` naming the missing field; `PATCH /api/router/search/providers/:id` ⇒ 200 view (a required field cannot be emptied: the check runs on the resulting shape before anything is written, so a refused patch leaves both the record and the credential row as they were); `DELETE /api/router/search/providers/:id` ⇒ 200 `{deleted:true}`, and deleting the active entry returns the selection to `null`; `POST /api/router/search/providers/:id/reveal` ⇒ `{id,key}`; `POST /api/router/search/providers/:id/test` ⇒ `{ok,providerId,status,latencyMs,code,message,sample}` — it calls the provider's real endpoint with one small query, records `lastTest`/`lastTestedAt`, and never throws a network failure outward (`code` is `AUTH`/`RATE_LIMIT`/`TIMEOUT`/`UNAVAILABLE`); `PUT /api/router/search/active` body `{providerId}` ⇒ `{activeProviderId,revision}` (404 for an entry that is not configured, `providerId:null` for the built-in path); `GET /api/router/search/resolve` ⇒ `{revision,active:{id,apiKey,accountId,endpoint}|null}`. Every write bumps `revision` by 1 so the harness's 15 s cache knows to re-read, and `GET /api/router/state` carries the same snapshot as `GET /api/router/search` under its `search` key. `BOXFOX_<PROVIDER>_SEARCH_URL` is a test-only override of a provider's base URL (the harness reads the same names for its own legs) — it is not a user-facing setting. The 10-step pipeline of `BOXFOX_SEARCH_PIPELINE=on` does not consult the selected source in v1: a known limit, recorded in `docs/testing/search-provider-e2e.md`.
OAuth: POST `/api/router/oauth/attempts` body `{connectionId}` => OAuthAttempt. GET `/api/router/oauth/attempts/:id` polls; DELETE cancels. Authorization URL opens in browser. Dedicated temporary loopback callback listener uses the embedded-client compatible `/oauth-callback` on port 51121 by default (configurable); complete state verified on server. Tokens never reach frontend. Failed bootstrap retains credential but sets project state required/failed so it is repairable.

Routing: POST `/api/router/aliases` body `{name,strategy,targets,enabled?}`; PATCH/DELETE `/api/router/aliases/:id`. PUT `/api/router/default` body ProviderDefault. Targets use saved connection IDs and real model IDs. GET `/api/router/keys`, POST body `{name,allowedModels?}` returns `{key,record}` (raw key once); DELETE `/api/router/keys/:id` revokes. GET `/api/router/usage` => RouterUsage[] (`cost`, `costBasis` and `estimated` per row). For allowedModels use public model identifiers from `/v1/models`: alias names or `connectionId/modelId`. Empty list means all enabled targets.

Internal POST `/v1/router/generate` body `{connectionId?,providerId?,modelId?,aliasId?,messages:[{role:'user',content:prompt}],stream:true,max_tokens:256}`. The harness reaches the same pipeline through admin POST `/api/router/chat` with that body shape plus optional `tools[]`: `{providerId,modelId}` there fans out over every enabled connection of the provider in `connectionOrder`, and each of those connections then walks its key ring. A provider/model selection uses configured account order and optional round robin. External POST `/v1/chat/completions` accepts OpenAI Chat body with `model` alias name or `connectionId/modelId`. Both use the same router pipeline. Streaming is OpenAI SSE (`data: {JSON}\n\n`, then `[DONE]`). Initial chunk includes `boxfox:{requestId,connectionId,modelId,aliasId}`; subsequent chunks contain choices[].delta.content/tool_calls/reasoning_content, terminal finish_reason, final usage if available. Deltas that carry only reasoning (`reasoning_content` or `reasoning`) are forwarded, not dropped; the non-stream response reports the accumulated text as `reasoning_content` when there is any. SSE errors are `{error:{code,message,retryable},boxfox:{...}}`, no DONE success after failure. Stop aborts fetch, server cancels upstream. Nonstream returns standard OpenAI response plus boxfox and actual usage.

Anthropic Messages ingress: POST `/v1/messages` accepts an Anthropic Messages body (`model`, `system` as string or text blocks, `messages` with `text`/`image`/`tool_use`/`tool_result` blocks, `tools[].input_schema`, `tool_choice`, `max_tokens` 1–64000, `stream`) and answers in Anthropic's own SSE dialect: `event: <type>\ndata: <JSON>\n\n` frames, `message_start` → `content_block_start`/`content_block_delta`/`content_block_stop` per block → `message_delta` → `message_stop`, and never `[DONE]`. POST `/v1/messages/count_tokens` returns `{input_tokens}` and never calls a provider; it estimates `ceil(chars/4)` over `system`, `tools` and messages (image payloads are not counted). Both routes authenticate with `x-api-key` or `Authorization: Bearer` against the same gateway-key store as `/v1/chat/completions` (Bearer is checked first, then `x-api-key`), and both refuse a model the key may not use before any provider call. `model` follows the same rule as every other route: alias name or `connectionId/modelId` — the router never infers a provider from a bare Anthropic model name such as `claude-sonnet-4-5`. Anthropic-only fields with no OpenAI-side equivalent (`top_k`, `metadata`, `mcp_servers`, `context_management`, …) are dropped, `thinking {type:'enabled',budget_tokens}` becomes the model's own `thinkingLevel` (≤4096 low, ≤12288 medium, else high), and a content block or image source the router cannot represent is a 400 instead of a silent drop. Errors are `{type:'error',error:{type,message}}` with the Anthropic error type for the router code (`authentication_error`, `permission_error`, `not_found_error`, `rate_limit_error`, `invalid_request_error`, `api_error`); a failure after the first frame arrives as an `event: error` frame and the stream ends without `message_stop`. Requests that carry a `claude-cli` user-agent are answered locally for Claude Code's housekeeping traffic (warm-up, its `{"title":…}` turn, title-instruction and topic-naming prompts) — only when the request has no tools — so those calls never reach a provider. Gemini-backed providers require their opaque `thought_signature` on a replayed tool call; the ingress remembers it per tool call id and re-attaches it on the `tool_result` round trip, because an Anthropic `tool_use` block has nowhere to carry it.

Model record (returned by `discover`, by `connections[].models` in `/api/router/state`, and by `/v1/models`): `{id,name,source,contextWindow,thinkingType,defaultThinking,thinkingLevels,stale,enabled,capabilities,...}` where `contextWindow` is a token count or `null`, `thinkingType` is `'effort'|'budget'|'fixed'|'none'` and `defaultThinking` is the level the provider publishes or `null`. Every `capabilities` value is one of `unknown|reported|verified|unsupported`: `reported` is evidence a payload or a user declaration produced but nobody verified, and a hand-typed declaration is written as `reported`, never under a word of its own. `contextWindow` comes from three tiers, in this order: a declaration the user made for that model (`contextWindowSource:'manual'`), the router's shipped name table when the model id matches it (`'documented'` — for a name in the table the table wins over whatever the provider reports, and the number the provider published is kept beside it as `contextWindowReported`), then the provider's own payload or documented adapter rule (`'reported'`); the harness's own floor (128000, `'fallback'`) is a runtime safety number and is never published as a model record. A name that matches nothing keeps `contextWindow:null`. `contextWindowSource` is one of `'manual' | 'documented' | 'reported' | null`, and `contextWindowReported` is the number the provider published or `null` (present only when it differs from the number in use, so the two can be compared). `thinkingType`/`defaultThinking`/`thinkingLevels` still come only from provider payloads or documented provider rules, never from model-name patterns; when a payload does not say, the record is `thinkingType:'none'`, `defaultThinking:null`, `thinkingLevels:[]`. A curated catalog that is not a live inventory is labelled `source:'static'`. The router translates the level per adapter on the wire: `effort` => `reasoning_effort` (OpenAI-compatible) or `thinkingLevel` (Gemini/Antigravity), `budget` => Anthropic `thinking.budget_tokens` (low/medium/high => 2048/8192/16384), and no thinking field is sent for `none`/`fixed` or when the model reports no thinking control. An adapter whose provider documents a different rule replaces that default: DeepSeek publishes `none|low|high|max` (default effort `high`, with `minimal`/`medium`/`xhigh` accepted as compatibility aliases for `low`/`high`), sends `none` as `reasoning_effort: none` because that is DeepSeek's own switch-off, and serves a restricted `tool_choice` with thinking off, which DeepSeek requires.

Model price: a model record may carry `pricing` — `{currency:'USD',unit:'per_million_tokens',input,cachedInput,cacheWriteInput,output,source,asOf,updatedAt}`, with a rate left `null` when its source did not publish it. `source` is `'manual'` (the user set a price for that model; also the shape of PATCH `/api/router/connections/:id` body `{modelPricing:{modelId,input,output,cachedInput?,cacheWriteInput?,clear?}}`, `asOf` a `YYYY-MM-DD` date and `updatedAt` a millisecond stamp), `'ping'` (the price the provider published in its own model list) or `'documented'` (the adapter's documented table, e.g. DeepSeek's, re-read at the hour of every call because those prices move by peak time; its published peak windows skip Chinese public holidays, a calendar the router does not ship, so a holiday hour is priced as working time and its estimate can read up to 2× high). PATCH body also accepts `{modelContextWindow:{modelId,contextWindow,clear?}}` (a per-model declaration for a model the connection already has; `clear:true` hands the row back to the name table or the provider, `modelId` the connection does not have is a `MODEL_NOT_FOUND` 404 and a number that is not a positive whole token count is an `INVALID_CONTEXT_WINDOW` 400), `{customModel:{id,name?,contextWindow?,capabilities?}}` and `{enabledModelIds:[...]}`; `customModel` is applied before `modelPricing`, so one PATCH can add a model and price it, and a price for a model the connection does not have is a `MODEL_NOT_FOUND` 404. A `manual` context window is never overwritten by a later scan, exactly like a `manual` price. A `manual` price is never overwritten by a later scan, hand-typed models survive a successful scan, and `clear:true` drops the manual price so the `ping`/`documented` price returns. A hand-typed row is a declaration, not a scan result: re-declaring the same id rewrites its `name` and the two flags the form owns (`vision`, `reasoning`), and the row stays routable while discovery is `'failed'` or `'degraded'` — a listing that never worked must not take the id the user typed off the routes. A probe that passes is evidence for one model only, so it leaves a listing error in place until a listing succeeds. `/v1/models` never carries prices. Connection records carry `costMode` (`'metered'` or `'included'`) and `lastDiscoveryAttemptAt` (epoch ms or `null`, stamped on every discovery attempt including failures).

Provider adapter interface (worker-owned `src/providers/index.mjs`): `createProviders({fetchImpl})` returns registry; each adapter has `discover({connection,credentials,signal})` => `{models,email?,projectId?,projectState?,credentials?}`, `generate({connection,credentials,body,signal})` async generator yielding `{type:'delta',delta:{content?,tool_calls?,role?}} | {type:'finish',finishReason:string} | {type:'usage',usage:{prompt_tokens?,input_tokens?,completion_tokens?,output_tokens?,total_tokens?,cached_tokens?,cache_read_input_tokens?,cache_creation_input_tokens?,reasoning_tokens?,cost?}}`; BoxFox normalizes prompt/input, cache-read/write, reasoning and total tokens before recording usage. Cost is recorded on every usage row in three tiers, in this order: a trusted value the provider reported is copied verbatim (`costBasis:'reported'`, `estimated:false`); otherwise the price already resolved on the model row is applied to the token counts (`costBasis` is that price's `'manual'|'ping'|'documented'` source, `estimated:true`), except when the connection is `costMode:'included'`, where our own arithmetic is skipped because the plan is already paid for; a figure the provider itself reported is copied verbatim on every connection, `included` ones included, because that number is the provider's own and the row shows its `costBasis`; otherwise nothing is recorded (`cost:null`, `costBasis:null`, `estimated:false`). Cost is never invented. `cost` stays null when no tier resolves a price; `estimated: true` marks a locally computed number and only `costBasis: 'reported'` repeats the provider's own figure. Client-facing `/v1/*` frames never carry an estimate. `quota({connection,credentials,signal})` => ProviderQuota. Antigravity additionally `oauthConfig`, `buildAuthUrl({redirectUri,state})`, `exchangeCode({code,redirectUri,signal})`, `refresh({credentials,signal})`. Credential shape `{apiKey?} | {accessToken,refreshToken?,expiresAt,projectId?,oauthClient:{clientId,clientSecret?},email?}`; refresh preserves issuer binding. Provider errors throw `{code,status,retryable,message}` via exported error helper or compatible Error. fetchImpl is an injected policy-enforcing fetch; no raw console credential/payload logging. Account/store persistence belongs to main worker.

OpenCode Free (`providerId:'opencode'`, `authModes:['anonymous']`, ported from 9Router v0.5.81 / commit a8c9d38 and re-measured against `https://opencode.ai/zen/v1` on 2026-09-21 with `Authorization: Bearer public`): the free tier answers only a request that looks like the OpenCode client. A `User-Agent` without a version (`opencode`) is refused `403 FreeTierError`, as are an empty `tools` array, `stream:false`, and a `ses_<32 hex>` session id; `opencode/1.18.31`, a `tools` set that contains the two decoy tools `bash` and `read` (description `This tool is currently unavailable and must not be used.`), `stream:true` and `ses_<12 hex><14 base62>` are accepted. The adapter therefore always streams upstream and assembles the answer itself when the caller asked for a non-streaming reply, always adds the decoys to the caller's `tools`, and always sends `x-opencode-session`/`x-opencode-request` in that shape: the session is derived from the conversation identity (a `session_id`/`sessionId` field in the request body when the caller sends one, otherwise one canonical session per connection and model, kept for six hours, capped at 200 entries) because the free tier accounts quota per session and a fresh session per request surfaces as `429`; the request id is derived from the session plus the last user turn, so a retry of one turn reuses one id. `muse-spark-*` ids speak the Responses API (`input`, `instructions`, `function_call`/`function_call_output` items), and on that wire `reasoning_effort` is refused `400`, so the level is translated to `reasoning:{effort,summary:'auto'}` with `minimal|low|medium|high|xhigh` (`none` is refused and is therefore omitted), prior `reasoning` items and their `encrypted_content` are stripped from the replayed `input` (they are only decryptable by the account that issued them), and a tool result that carries an image is sent twice — a text-only `function_call_output` plus a following user turn holding the `input_image` — because the array-output form answers `200` with an empty body while the split form reads the image correctly. Non-`-free` ids are discovered but left disabled: without a credential they answer `401 AuthError`. Token usage is read from `response.completed`; a `403` in this shape is reported as a non-retryable `AUTH` refusal that names the client-shape rule, a `429` as a retryable `RATE_LIMIT`, and a stream that fails after `200` throws instead of ending as a successful finish.
