## 5. Top concrete problems (ranked, with evidence)

1. **Both workflows are mode-locked, so the main agent cannot invoke them on its own.** `/research`/`/design` are MODE commands (`runtime_commands.py:419/468`); tier-3 research outside mode raises `RESEARCH_MODE_REQUIRED` (`research_runtime.py:931`); design tools outside mode raise `DESIGN_MODE_REQUIRED` (`runtime.py:4719`); mode turns drop all write tools (`RESEARCH_MODE_EXCLUDED_TOOLS` / `DESIGN_MODE_EXCLUDED_TOOLS`), so mode turns can only hand off at the end. `research_suggest` explicitly "never changes the session config". Whoever redesigns this must remove or relax the mode gate rather than add loops on top.
2. **Research mode never closed the loop in live runs.** 2 live runs (addendum) and 6 live runs (verification doc): dossiers `quality_ok=0`, no research review recorded, 0 dossier files written in the 6-run round, 4/6 runs killed by provider 502 at minute 8.5–14, tier-2 turn budget is the hard blocker; benchmark (`tier-r1`) still `blocked`/`measured:false`.
3. **Search supply is the declared bottleneck** (`web.py:10-21` provider measurement; addendum: Firecrawl 403 + no keys).
